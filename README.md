# PANOPTICON

*Population-aware exploration of bacterial pangenomes.*

PANOPTICON is a modular toolkit for exploring **population structure, accessory-genome variation, and ecological signal** in bacterial pangenome data.

It is designed for the stage between pangenome construction and formal downstream modelling. PANOPTICON helps determine whether an apparent association with host, geography, phenotype, or environment is broadly distributed across a population or largely explained by particular lineages.

The central principle is simple:

> A bacterial pangenome should be interpreted as a population-genetic object, not only as a feature matrix.

---

## Overview

PANOPTICON supports pangenomes generated by:

- **Panaroo**
- **PIRATE**

Both formats are converted into a common internal representation before analysis. Downstream scripts therefore work with the same gene-family matrix, annotations, prevalence estimates, and summary statistics regardless of the upstream pangenome tool.

PANOPTICON is **not** a genome annotation or pangenome construction pipeline. Assemblies must first be annotated and processed using external tools.

### Typical workflow

```text
Genome assemblies
      │
      ▼
Annotation
Bakta or Prokka
      │
      ▼
Pangenome construction
Panaroo or PIRATE
      │
      ├── gene presence/absence matrix
      ├── gene-family annotations
      └── core-genome alignment
      │
      ▼
PANOPTICON
      │
      ├── pangenome composition
      ├── gene-frequency distributions
      ├── PCA / MDS / UMAP
      ├── rarefaction and accumulation curves
      ├── host and ecological association
      ├── lineage-aware comparisons
      └── exploratory figures and tables
      │
      ▼
Phylogenetics, GWAS, source attribution,
machine learning, and manuscript development
```

---

## Why PANOPTICON?

Associations in bacterial genomic datasets are commonly confounded by:

- clonal population structure
- uneven sampling
- lineage-specific gene content
- host-restricted or geographically restricted lineages
- recombination
- assembly and annotation quality
- differences in study design

A gene may appear associated with a host simply because it is common in one successful clonal complex. Likewise, a clear ordination pattern may reflect study provenance rather than biology.

PANOPTICON is intended to make these patterns visible before stronger claims are made.

Typical questions include:

- How strongly structured is the accessory genome?
- Which metadata variables explain the largest differences?
- Are host-associated genes distributed across multiple lineages?
- Does a signal persist after stratifying by clonal complex or sequence type?
- Is observed diversity driven by ecology, host physiology, geography, or sampling?
- Are particular comparisons sufficiently balanced for GWAS or machine learning?
- Where does variation occur: between lineages, within lineages, or across environments?

# Core functionality

Current functionality includes:

- loading and standardising Panaroo and PIRATE outputs
- pangenome composition summaries
- core, soft-core, shell, and cloud classification
- gene-frequency distributions
- per-genome gene-count summaries
- PCA, MDS, and optional UMAP
- rarefaction and pangenome accumulation curves
- group-specific rarefaction
- metadata-aware visualisation
- host and ecological association testing
- lineage-stratified comparisons
- CMH association tests controlling for population structure
- PERMANOVA and related multivariate analyses
- integration with phylogenetic and GWAS outputs
- publication-oriented tables and figures

The scripts are deliberately modular. Users can run only the analyses relevant to their dataset rather than committing to a single automated workflow.

# Installation

## Requirements

PANOPTICON is intended for Linux or a Unix-like HPC environment.

A working Conda or Mamba installation is recommended.

The main dependencies are:

- Python 3.11
- pandas
- NumPy
- SciPy
- matplotlib
- scikit-learn
- scikit-bio
- Biopython
- statsmodels
- DendroPy
- ETE Toolkit
- UMAP
- svgwrite

Some scripts may use only a subset of these packages.

## 1. Clone the repository

Choose a software or project directory:

```bash
cd /path/to/software
git clone https://github.com/Benizao1980/PANOPTICON.git
cd PANOPTICON
```

To update an existing installation:

```bash
cd /path/to/PANOPTICON
git pull origin main
```

```bash
conda create -n panopticon \
```

From the repository directory:

```bash
python -m py_compile \
  pangenome_io.py \
```

Inspect the available command-line options:

```bash

```


To make this permanent:

```bash
echo 'export PATH="/path/to/PANOPTICON:$PATH"' >> ~/.bashrc
```

# Input data

PANOPTICON requires:

1. a completed Panaroo or PIRATE output directory
2. optional isolate metadata for grouped or association analyses

## Panaroo

The preferred Panaroo input directory contains:

```text
gene_presence_absence.Rtab
gene_presence_absence.csv
summary_statistics.txt
```

Additional useful files include:

```text
pan_genome_reference.fa
final_graph.gml
core_gene_alignment.aln
core_gene_alignment_filtered.aln
```

### Main files

`gene_presence_absence.Rtab`

- binary presence/absence matrix
- preferred for large datasets
- substantially faster and less memory-intensive than parsing the full CSV

`gene_presence_absence.csv`

- gene-cluster identifiers
- gene names and annotations
- isolate-specific locus tags
- copy-number and paralogue information

`summary_statistics.txt`

- optional Panaroo summary information

When `gene_presence_absence.Rtab` is unavailable, PANOPTICON can derive a binary matrix from `gene_presence_absence.csv` using:

```text
--panaroo-from-csv
```

This is useful for testing but is not recommended for very large datasets.

## PIRATE

The preferred PIRATE input directory contains:

```text
binary_presence_absence.fasta
PIRATE.gene_families.ordered.tsv
PIRATE.pangenome_summary.txt
```

PANOPTICON also supports common alternative PIRATE filenames.

`binary_presence_absence.fasta`

- binary gene-family matrix
- typically encoded as A/C or 0/1

`PIRATE.gene_families.ordered.tsv`

- gene-family definitions
- prevalence and threshold information
- isolate-specific gene or allele assignments

`PIRATE.pangenome_summary.txt`

- pangenome summary statistics

## Metadata

Metadata may be tab-separated or comma-separated.

A typical table is:

```text
sample	host	country	CC	ST	phenotype
isolate_001	pig	Poland	CC398	ST398	resistant
isolate_002	wild_boar	Poland	CC398	ST398	susceptible
isolate_003	cow	Germany	CC97	ST97	susceptible
```

The isolate identifier must match the genome names in the pangenome output.

Before analysis, check:

- identifiers are unique
- spelling and capitalisation are consistent
- missing values are encoded consistently
- host categories are biologically meaningful
- lineage columns such as CC or ST are available where possible
- metadata and pangenome identifiers overlap as expected

# Shared input layer

PANOPTICON uses `pangenome_io.py` to convert Panaroo and PIRATE outputs into a common schema.

The main interface is:

```python
from pangenome_io import load_pangenome

pg = load_pangenome(
    tool="panaroo",
    outdir="/path/to/panaroo_output"
)
```

or:

```python
pg = load_pangenome(
    tool="pirate",
    outdir="/path/to/PIRATE_out"
)
```

The returned object contains:

```python
pg.presence_absence
pg.family_metadata
pg.summary
```

### `presence_absence`

A binary table with:

```text
rows    = genomes
columns = gene families
values  = 0 or 1
```

### `family_metadata`

A standardised table with fields including:

```text
gene_family
gene_name
annotation
n_genomes
prevalence
source_tool
```

### `summary`

A standardised summary containing:

```text
n_genomes
total_families
core
soft_core
shell
cloud
```

Downstream scripts should use this common representation rather than parsing Panaroo or PIRATE files directly.

# Quick start

## Inspect a Panaroo pangenome

Preferred use with the Rtab and CSV files:

```bash
python pangenome_io.py \
  --pangenome-tool panaroo \
  --pangenome-out /path/to/panaroo_output
```

When only `gene_presence_absence.csv` is available:

```bash
python pangenome_io.py \
  --pangenome-tool panaroo \
  --pangenome-out /path/to/panaroo_output \
  --panaroo-from-csv
```

## Inspect a PIRATE pangenome

```bash
python pangenome_io.py \
  --pangenome-tool pirate \
  --pangenome-out /path/to/PIRATE_out
```

## Generate initial pangenome summaries

Panaroo:

```bash
python pangenome_plotting.py \
  --pangenome-tool panaroo \
  --pangenome-out /path/to/panaroo_output \
  --outdir panopticon_plots \
  --pangenome-bars \
  --gene-freq \
  --gene-counts
```

PIRATE:

```bash
python pangenome_plotting.py \
  --pangenome-tool pirate \
  --pangenome-out /path/to/PIRATE_out \
  --outdir panopticon_plots \
  --pangenome-bars \
  --gene-freq \
  --gene-counts
```

## PCA with metadata

```bash
python pangenome_plotting.py \
  --pangenome-tool panaroo \
  --pangenome-out /path/to/panaroo_output \
  --outdir panopticon_pca \
  --pca \
  --meta metadata.tsv \
  --meta-col host
```

## Rarefaction

```bash
python pangenome_plotting.py \
  --pangenome-tool panaroo \
  --pangenome-out /path/to/panaroo_output \
  --outdir panopticon_rarefaction \
  --rarefaction
```

For group-specific rarefaction:

```bash
python pangenome_host_association.py \
  --pangenome-tool panaroo \
  --pangenome-out /path/to/panaroo_output \
  --meta metadata.tsv \
  --outdir host_association \
  --group-col host \
  --structure-col CC \
  --rarefaction-per-group
```

## Lineage-aware host association

```bash
python pangenome_host_association.py \
  --pangenome-tool panaroo \
  --pangenome-out /path/to/panaroo_output \
  --meta metadata.tsv \
  --outdir host_association \
  --group-col host \
  --structure-col CC \
  --assoc \
  --min-group-n 30 \
  --min-prevalence 0.01 \
  --max-prevalence 0.99
```

Equivalent analyses of PIRATE outputs use:

```text
--pangenome-tool pirate
```

# Working with large datasets

Very large pangenomes can require substantial memory and CPU time.

For datasets containing several thousand genomes:

- use `gene_presence_absence.Rtab` where possible
- avoid loading the full Panaroo CSV unless annotation detail is required
- run lightweight summaries before PCA, MDS, UMAP, or permutation tests
- run expensive analyses as separate HPC jobs
- retain and back up completed pangenome outputs
- check sample overlap before allocating large resources
- consider representative or lineage-stratified analyses when biologically appropriate

## Example Slurm job

```bash
#!/bin/bash
#SBATCH --job-name=panopticon
#SBATCH --output=panopticon_%j.out
#SBATCH --error=panopticon_%j.err
#SBATCH --time=24:00:00
#SBATCH --mem=128G
#SBATCH --cpus-per-task=4

source ~/.bashrc
conda activate panopticon

cd /path/to/PANOPTICON

python pangenome_plotting.py \
  --pangenome-tool panaroo \
  --pangenome-out /path/to/panaroo_output \
  --outdir /path/to/panopticon_results \
  --pangenome-bars \
  --gene-freq \
  --gene-counts
```

Resource requirements depend on:

- number of genomes
- number of gene families
- matrix density
- selected analysis
- number of rarefaction replicates
- dimensionality-reduction method
- availability of an Rtab file

PCA, MDS, UMAP, pairwise distance calculations, and repeated rarefaction should be benchmarked before being applied to very large datasets.

# Recommended analytical order

A sensible first-pass workflow is:

## 1. Validate the input

Confirm:

- expected number of genomes
- expected number of gene families
- metadata overlap
- duplicate-free sample identifiers
- plausible genome and gene counts

## 2. Describe the pangenome

Generate:

- core, soft-core, shell, and cloud summaries
- gene-frequency distributions
- per-genome gene counts
- accumulation curves

## 3. Explore population structure

Use:

- PCA
- MDS
- UMAP
- core-genome phylogeny
- MLST, clonal-complex, or lineage labels

## 4. Add ecological and phenotypic metadata

Overlay:

- host
- source
- geography
- phenotype
- study
- year
- lineage

## 5. Test robustness to lineage structure

Repeat comparisons:

- within major clonal complexes
- using stratified association tests
- after excluding highly clonal or oversampled groups
- with balanced or downsampled datasets where appropriate

## 6. Progress to formal modelling

Use the exploratory results to guide:

- GWAS
- source attribution
- machine learning
- recombination analysis
- gene gain/loss analysis
- focused lineage studies

# Interpretation and validation

PANOPTICON results should be interpreted alongside population structure.

Before making biological claims, ask:

1. Is the association present in more than one lineage?
2. Could the signal be driven by a single clonal complex?
3. Is sampling balanced across groups?
4. Does study, country, or year explain the same pattern?
5. Are gene counts associated with assembly quality?
6. Do host categories reflect ecology, physiology, or both?
7. Is the comparison supported by enough independent evolutionary events?
8. Does the result persist under alternative filtering thresholds?
9. Is the signal compatible with the core-genome phylogeny?
10. Is functional or experimental validation possible?

PANOPTICON is intended to identify strong hypotheses, but it should also expose analyses that are not yet robust enough for stronger conclusions.

# Example project: animal-associated *Staphylococcus aureus*

## 1. Genome annotation

Annotate all assemblies consistently using Bakta or Prokka.

Example with Bakta:

```bash
bakta \
  --db /path/to/bakta_db \
  --output output/sample_001 \
  --prefix sample_001 \
  --threads 8 \
  sample_001.fasta
```

Collect the resulting `.gff3` files.

Consistency is more important than mixing annotations from multiple pipelines or versions.

## 2. Panaroo pangenome

Run Panaroo on all GFF3 files:

```bash
panaroo \
  -i /path/to/gffs/*.gff \
  -o panaroo_output \
  --clean-mode strict \
  --remove-invalid-genes \
  -t 8
```

For a core-genome alignment:

```bash
panaroo-msa \
  -a core \
  --core_threshold 0.98 \
  -o panaroo_output \
  --aligner mafft \
  -t 8
```

Important outputs:

```text
gene_presence_absence.csv
gene_presence_absence.Rtab
summary_statistics.txt
core_gene_alignment.aln
core_gene_alignment_filtered.aln
```

Use the filtered core alignment for maximum-likelihood phylogenetics where appropriate.

## 3. PANOPTICON

Inspect the pangenome:

```bash
python pangenome_io.py \
  --pangenome-tool panaroo \
  --pangenome-out panaroo_output
```

Generate initial summaries:

```bash
python pangenome_plotting.py \
  --pangenome-tool panaroo \
  --pangenome-out panaroo_output \
  --outdir panopticon_results \
  --pangenome-bars \
  --gene-freq \
  --gene-counts \
  --pca
```

Run host-aware analyses:

```bash
python pangenome_host_association.py \
  --pangenome-tool panaroo \
  --pangenome-out panaroo_output \
  --meta metadata.tsv \
  --outdir host_association \
  --group-col host \
  --structure-col CC \
  --rarefaction-per-group \
  --assoc
```

Potential comparisons include:

- pigs versus wild boar
- pigs versus cattle
- pigs versus chickens
- livestock versus wildlife
- ecologically connected versus physiologically similar hosts
- within-lineage versus between-lineage accessory-gene sharing

These analyses should be interpreted alongside a core-genome phylogeny and sampling structure.
